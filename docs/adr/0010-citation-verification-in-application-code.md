# ADR-0010: Citation verification and source integrity in application code

- **Status:** accepted
- **Date:** 2026-08-30
- **Phase:** 4

## Context

In Retrieval-Augmented Generation (RAG) systems, LLMs can hallucinate document identifiers, misattribute factual claims, or follow prompt-injection instructions embedded in untrusted document text.

The system requires an authoritative mechanism to:
1. Guarantee that returned source citations correspond only to chunks actually retrieved and admitted into the LLM context.
2. Prevent prompt injection within document text from hijacking system behavior or citation provenance.
3. Keep raw vector embeddings out of API responses and logs.

## Options

| Option | Pros | Cons |
|---|---|---|
| Trust LLM-generated citation JSON | Zero application-level citation mapping logic | Model can hallucinate document IDs; vulnerable to prompt injection; impossible to audit reliably |
| LLM-as-judge citation validator | Dynamic semantic checking | High latency and doubled LLM cost; non-deterministic; prone to validator model hallucinations |
| Deterministic Application-Enforced Citation & Source Attribution | 100% authoritative; zero latency overhead; independent of model output; tamper-proof against document injection | Requires strict prompt formatting conventions (`[S1]`, `[S2]`) |

## Decision

Enforce citation integrity and source provenance deterministically in application code within `RAGService`:

1. `RetrievalService` retrieves candidate chunks filtered strictly by caller tenant ID and role clearance ceiling.
2. `RAGService` formats admitted chunks into a bounded reference context with deterministic labels (`[S1]`, `[S2]`, ...).
3. The prompt explicitly isolates untrusted document content and instructs the model to ignore any system prompt overrides inside document text.
4. `RAGResponse.sources` is populated directly from the application's admitted retrieval records (`RAGSource`), completely independent of the text generated by the LLM.
5. If retrieval yields zero chunks, LLM generation is skipped entirely, returning a stable insufficient-evidence answer.

## Consequences

- **What this buys:** Uncompromising citation accuracy, resistance to prompt-injection hallucination, deterministic source provenance, and elimination of unnecessary LLM invocations on zero-result queries.
- **What this costs:** The LLM's in-text citations are tied to structured labels (`[S1]`) rather than open-ended inline bibliographic links.
- **What it makes harder:** Extracting fine-grained sub-sentence character spans requires explicit parsing rules.

## Revisit when

Phase 9 evaluation harness introduces automated groundedness and citation precision metrics requiring automated span-level alignment scoring.
